= ngspice Container

`debian:bookworm-slim` + `ngspice`. Runs Stage 1 (architecture sizing)
of the two-stage circuit emulation model described in `kicad/README.adoc`.

== Stage 1 vs Stage 2

This container only runs Stage 1: a hand-written behavioral model
(`kicad/pb3-architecture-sizing.cir`) used to pick topology and nominal
values *before* the schematic exists. A passing run here proves the
idealized model is self-consistent — it does not verify the real
TP4056 -> DW01A/FS8205A -> TPS62200 circuit in
`pb3-replacement.kicad_sch`/`.kicad_pcb`.

Stage 2 — netlist-derived simulation of the actual KiCad schematic — is
the step that would verify the real design. It is not implemented yet:
`pb3-replacement.kicad_sch` is currently a block/documentation diagram
with global labels only (see "PCB Routing" in `kicad/README.adoc`), not
real pin-to-pin wiring, so a `kicad-cli sch export netlist` of it would
not produce a meaningful netlist. Stage 2 becomes possible once the
schematic carries real symbol pins and wiring for `U1`/`U2`/`Q1`/`U3`/`D1`
matching the PCB. See `kicad/README.adoc` for the tracked gap and what
unblocks it.

== Build & Run

[source,bash]
----
docker build -t aiwa-pb3-ngspice containers/ngspice
docker run --rm \
  -v "$PWD/kicad":/work:ro \
  -v "$PWD/results/circuit":/results \
  aiwa-pb3-ngspice \
  -b -o /results/pb3-architecture-sizing.log /work/pb3-architecture-sizing.cir
----

Or run `run.sh` — it does the same build-and-run in one call.

For interactive exploration (waveform plotting, live parameter sweeps,
graphical schematic-probe tools) instead of this batch invocation, see
"Interactive Exploration & Physical POC Loop" in `kicad/README.adoc`.

== Files

* `Dockerfile` — the image.
* `run.sh` — local convenience wrapper (build, run, write to `results/circuit/`).
