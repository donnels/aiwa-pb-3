`pb3-replacement.kicad_pro` (with its `.kicad_sch`/`.kicad_pcb`) is the
living electrical design for the replacement pack: a 68×17.8×8mm board that
takes USB-C 5V in and delivers a regulated 2.0-2.4V deck rail from a 1S
LiPo cell.

== Component Selection

Each part below was picked from the candidates surveyed in
`research/README.adoc`, chosen for SOT-23-6 footprints (small enough for
the enclosure) and for matching the behavior already proven on the clone
teardown boards.

CN3058E (charger)::
Linear Li-ion/LiPo charge management IC. Takes the USB-C 5V rail, applies
CC/CV charging to the cell, and needs only a handful of external passives
— important with almost no board area to spare.

DW01A + FS8205A (protection)::
Discrete battery management system on the cell tabs. DW01A senses cell
voltage and current; FS8205A is the dual N-MOSFET it drives to cut the
path on overvoltage, undervoltage, or overcurrent/short. Chosen instead of
trusting the charger or buck stage alone, so a fault anywhere downstream
still leaves the cell protected.

Buck regulator (TPS61023-class)::
Steps the ~3.7V cell rail down to the 2.0-2.4V the deck expects. The
feedback resistor sets the output: 100kΩ gives the PB-S5 clone's default
2.4V; the forum's 120kΩ swap gives 2.1V. Extrapolating those two points
puts 2.0V at roughly 130kΩ — an unverified estimate, not a datasheet
value. `pb3-replacement.cir` models 2.0V directly; confirm the real
resistor against the vendor datasheet and bench measurement before
fabrication.

OVP clamp (Zener/TVS)::
Added on top of what the clone boards do: clamps the output below 3V if
the buck stage fails, so the deck never sees the raw 3.7V cell rail.

== Circuit Emulation

`pb3-replacement.cir` is a system-level ngspice model of the proposed
pack. It approximates the CN3058E charger, 1S LiPo, DW01A/FS8205A
protection, 2.0V buck regulator, 200mA deck load, and output clamp with
behavioral sources. It is useful for checking operating points and
assumptions. It does not validate the real IC compensation network,
stability, thermal behavior, or the unverified AIWA connector pinout.

Run it with ngspice:

[source,bash]
----
ngspice -b -o pb3-replacement.log pb3-replacement.cir
grep -E 'vout_|load_current|vbat' pb3-replacement.log
----

Expected results: ~1.98V at the deck output, 198mA load current, 3.7V
at the idealized cell. The model hard-codes a 2.0V buck target — it
does not use the ~130kΩ feedback-resistor estimate above, which is for
the real IC's feedback divider, not this behavioral model. Verify with
vendor SPICE models and bench measurements before connecting an AIWA
deck. This is the electrical half of the compliance check; the
mechanical half is the OpenSCAD fit check.

== PCB Routing

`pb3-replacement.kicad_pcb` places footprints for the 1S protection/buck
power path (`J1` USB-C, `U1` TP4056 charger, `U2` DW01A protection IC,
`Q1` FS8205A dual-FET, `U3` buck regulator, `J2` deck connector, `BT1`
LiPo cell) but the schematic (`pb3-replacement.kicad_sch`) is a
block/documentation diagram with global labels only, not real pin-to-pin
wiring, and the generic pad numbering on each footprint has no documented
mapping to the chips' real pin functions. Nets and copper traces were
added directly to the PCB (not derived from the schematic) using
verified, datasheet-cited pinouts for the actual parts placed on the
board:

* TP4056 (SOIC-8): 1=TEMP, 2=PROG, 3=GND, 4=VCC, 5=BAT, 6=~STDBY, 7=~CHRG, 8=CE.
* DW01A (SOT-23-6): 1=OD, 2=CS, 3=OC, 4=TD, 5=VCC, 6=GND — cross-checked
  against Fortune Semiconductor datasheet DW01A-DS-12_EN Rev 1.2, Section 6.
* FS8205A (SOT-23-6): 1=S1, 2/5=D12 (common drain), 3=S2, 4=G2, 6=G1.
* TPS62200DBV (SOT-23-5): 1=VIN, 2=GND, 3=EN, 4=FB, 5=SW. The PCB
  footprint is labelled `TPS61023`, but the real TI TPS61023 is a 6-pin
  SOT-563 part that doesn't match this board's 5-pad SOT-23-5 footprint.
  The schematic's actual symbol for `U3` is `Regulator_Switching:TPS62200`
  (a real SOT-23-5 buck), so the TPS62200 pinout was used to route the 5
  pads that exist — the footprint name is a pre-existing naming
  inconsistency in the repo, left unchanged.

Routed nets: `VBUS`, `GND` (includes TEMP/CE tied low and the
DW01A/FS8205A current-sense node), `VBAT` (cell/protected-positive rail,
includes `EN` tied high for an always-on regulator), `VBAT_RAW_NEG`
(raw/unprotected cell negative — kept separate from `GND` so the
protection circuit still does its job), and the DW01A→FS8205A gate
signals `OD`/`OC`.

Several pins are intentionally left as single-pad, unrouted nets
(`NC_PROG`, `NC_STDBY`, `NC_CHRG`, `NC_TD`, `NC_FB`, `NC_SW`,
`NC_VOUT`) because the passives their function depends on — the PROG
resistor, charger status LEDs, the buck's inductor, the FB feedback
divider, and the output capacitor — do not exist as footprints in this
PCB revision (they're only referenced in the block-diagram schematic).
`kibot.yaml`'s `ignore_unconnected` preflight option keeps DRC clean
despite this. Adding those passives and wiring them in is a follow-up,
not part of this routing pass.

This is a best-effort prototype routing based on standard reference-design
pinouts, not a verified production layout — confirm every net against the
real datasheets and bench-test before fabrication, same as the existing
disclaimers on connector pinout and the feedback resistor value above.

== 3D Exports & Renders

Alongside the fabrication outputs (gerbers, drill, position files),
`kicad-cli` (KiCad 9, `pcb export`/`pcb render`) produces:

* `pb3-replacement.step` — STEP solid model, for any MCAD tool.
* `pb3-replacement.glb` — binary glTF, converted to
  `results/cad/pb3-replacement-board.stl` by the `containers/trimesh`
  container (rescale, re-axis, re-origin — see its README).
* `pb3-replacement-render-top.png` / `-render-iso.png` — photorealistic
  raytraced renders of the finished board.

.Isometric render of the replacement board
image::pb3-replacement-render-iso.png[]

The STL feeds `openscad/pb3-fit-check.scad` — see "Mechanical Design
(OpenSCAD)" for the fit-check render.
